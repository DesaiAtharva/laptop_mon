## 2. Core Scenarios to Build & Validate

1. **Complete Lifecycle Flow (Happy Path)**:
   - Admin generates enrollment token.
   - Agent exchanges token via `/api/agent/enroll`, obtains per-device credential.
   - Agent pulls effective policy via `/api/agent/policy`.
   - Agent sends heartbeat via `/api/agent/heartbeat`.
   - Agent logs foreground app activity and idle events to local journal and syncs batch to `/api/agent/events/batch`.
   - Agent spools screenshot, requests upload intent via `/api/agent/screenshots/upload-intents`, uploads image to object storage, and finalizes via `/api/agent/screenshots/complete`.
   - Timeline reconstruction triggers and produces intervals and daily aggregates.
   - Reports API (`/api/reports/daily`, `/api/reports/timeline`, `/api/reports/app-usage`) returns accurate, reconciled metrics.
   - Verification: Local journal pruned, storage object key/size/checksum verified, SQL foreign keys & unique constraints intact.

2. **Partial Batch Acceptance & Error Partitioning (E36)**:
   - Agent submits batch containing a mix of valid events and malformed/anomalous events.
   - Server returns partial acceptance status (`accepted` vs `rejected`).
   - Agent deletes accepted events from local journal while retaining unaccepted events for gap handling.

3. **Lost Response & Idempotent Replay (E02, E03, E31)**:
   - Agent submits event batch; server commits to DB.
   - Response is simulated lost/interrupted.
   - Agent retries identical batch.
   - Server recognizes duplicates via `(device_id, event_id)` idempotency, returns `already_accepted`, and avoids double-counting.
   - Agent successfully purges duplicates from local journal.

4. **Revoked Device & Upload Cessation (E38)**:
   - Admin revokes device via `/api/devices/{id}/revoke`.
   - Subsequent agent heartbeat, event batch, or screenshot intent receives HTTP 403 Forbidden.
   - Agent marks itself revoked, stops uploads, and holds pending events locally without infinite network thrashing.

5. **Version Mismatch & Outdated Agent (E16)**:
   - Policy sets `min_agent_version = "2.0.0"`.
   - Agent running `1.0.0` attempts upload or policy pull.
   - Server returns policy / error signaling update required.

6. **Two-Phase Screenshot Protocol & Intent Expiry (E51, E52, E53)**:
   - Expired upload intent cannot be completed (HTTP 410 / 400).
   - Duplicate finalize calls are idempotent.
   - S3/storage object existence, size, and SHA256 checksum are strictly validated before DB status becomes `finalized`.

7. **Policy Change Propagation & Dynamic Reconfiguration (E37, E70)**:
   - Admin patches tenant policy (idle threshold, capture windows, exclusion rules).
   - Agent queries `/api/agent/policy`, receives updated policy version, and applies new parameters.

8. **Multi-Tenant Concurrent Isolation (E45, E46)**:
   - Two separate tenants (Tenant A and Tenant B) with distinct devices run concurrent workflows.
   - Agent for Tenant A cannot access, query, or affect Tenant B data.
   - Cross-tenant queries return 404 or 403.
   - Reports for Tenant A contain 0 metrics from Tenant B.

9. **Large Offline Backlog Replay (7-Day Simulation)**:
   - Agent accumulates simulated 7-day backlog of events across session, active, and idle states while offline.
   - Agent comes online and transmits backlog in bounded batches.
   - Server ingests, deduplicates, and reconstructs timelines without data loss or duplicate interval creation.

## 3. Direct Layer Invariant Checks

| Layer | Invariant Verification |
|---|---|
| **Agent Journal** | `get_pending_events()` contains only unconfirmed events; confirmed events are physically deleted; queue depth reflects actual disk state. |
| **Agent Spool** | Spooled files are deleted only after verified finalize completion; quarantine works on corrupt files. |
| **Database** | Unique constraints: `(device_id, event_id)` on `activity_events`, `(device_id, local_date, calc_version)` on `daily_metrics`. No orphan intervals or batches. |
| **Object Storage** | `storage.get_object(key)` returns exact byte payload; SHA256 matches `screenshots.checksum`; size matches `screenshots.file_size`. |
| **Reports API** | $\sum \text{duration\_seconds} = \text{total\_duration}$; active + idle + gap partition correctly. |
