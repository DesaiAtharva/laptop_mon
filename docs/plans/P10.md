# Implementation Plan — Prompt P10: Security, Privacy, Observability and Disaster Recovery

## 1. Objectives & Scope
Adhering strictly to **`AGENTS.md`** and **`docs/spec/SPEC.md`** (§3.2, §11, §12, §15, §17.1):
- **Requirements:**
  - `REQ-3-1`: MUST use TLS on all transport, never disabled (§3.2).
  - `REQ-11-4`: Each threat in threat model MUST have an automated or documented test (§11.4).
  - `REQ-12-2`: Agent silence alerts MUST account for sleep and work hours (§12.2).
- **Edge Cases:**
  - `E06`: TLS certificate invalid or expired (strict fail-closed, no unverified bypass).
  - `E48`: Admin account compromised (session revocation, token purging, audit trail).
  - `E77`: MySQL failover or deadlock (resilient transactions with exponential backoff).
  - `E78`: Database migration fails (expand-then-contract checks).
  - `E80`: Stale or cross-tenant cache (tenant cache isolation and invalidation).
  - `E86`: Backup restore needed (MySQL backup/restore scripts, integrity verifier, RTO/RPO drill runbook).
  - `E87`: Region or provider outage (degraded mode runbook, object storage failover procedures).
  - `E88`: Logs or crash dumps contain secrets (structured JSON logging with robust redaction filters).

## 2. Architecture & Deliverables

### 2.1 Structured Logging & Redaction Filter (E88)
- File: `backend/apps/common/logging.py`
- Implements `SecretRedactingFilter` and `JSONFormatter`:
  - Automatically redacts sensitive patterns: Bearer tokens, JWTs, API keys, passwords, authorization headers, presigned S3 URLs, window titles (when redacted), and credit cards.
  - Test `test_E88_logs_contain_no_secrets`: verifies that logging sensitive strings produces redacted output `[REDACTED]`.

### 2.2 Health, Readiness & Observability Endpoints (§12.1, §12.3)
- Files: `backend/apps/common/views.py`, `backend/apps/common/urls.py`
- `GET /health/live`: Liveness check (200 OK).
- `GET /health/ready`: Readiness check testing database query, Redis cache access, and S3 object storage reachability.
- `GET /metrics`: Prometheus-compatible exposition format exposing SLO metrics (request latency, device counts, queue depths, error rates).

### 2.3 Agent Silence Alert Engine Accounting for Sleep and Work Hours (REQ-12-2)
- File: `backend/apps/devices/alerts.py`
- Function: `evaluate_device_silence(device, current_time=None)`
- Logic:
  - Computes silence duration: `current_time - device.last_seen_at`.
  - Determines if `current_time` falls within policy `work_start_time` and `work_end_time` on configured `work_days`.
  - Checks if last reported state was `asleep` or `locked`.
  - Suppresses silence alerts during non-work hours, weekends, or system sleep/lock periods.
  - Raises alert only when a device is unexpectedly silent during active work hours.

### 2.4 Security Hardening & Headers (§3.2, §15.2)
- File: `backend/apps/common/middleware.py`
- Implements:
  - `SecurityHeadersMiddleware`: Injects CSP (`Content-Security-Policy`), HSTS (`Strict-Transport-Security`), `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
  - `RequestSizeLimiterMiddleware`: Binds payload size to 10MB (or 1MB for standard JSON) returning HTTP 413 for oversized requests.

### 2.5 Production Deployment Configuration (§15.2)
- Files in `deploy/`:
  - `deploy/nginx/nginx.conf`: Production reverse proxy configuration terminating TLS, enforcing rate limits, proxying API and ingestion.
  - `deploy/docker-compose.prod.yml`: Multi-container production deployment composing separate API, ingestion, Celery worker, Celery beat scheduler, MySQL, Redis, MinIO, and Nginx.

### 2.6 Disaster Recovery, Backup & Restore (§15, E86, E87)
- Files in `scripts/dr/`:
  - `scripts/dr/backup_mysql.py`: Automated MySQL backup generating compressed, checksummed SQL dumps with metadata.
  - `scripts/dr/restore_mysql.py`: Validated restore procedure with pre/post-checks.
  - `scripts/dr/verify_db_storage_consistency.py`: Audit script validating referential integrity between MySQL `screenshots` rows and MinIO/S3 object keys.
- Runbook: `docs/runbooks/disaster-recovery.md` detailing RTO (4 hours) / RPO (1 hour) per plan tier, backup schedules, and restore drills.

### 2.7 Threat Model & Compliance Documents (§11.3, §11.4, §12.2, §17.1)
- `docs/threat-model.md`: Complete matrix mapping each row of §11.4 to test evidence.
- `docs/runbooks/incident-response.md`: Step-by-step incident response procedures.
- `docs/privacy/employee-notice-template.md`: First-run employee transparency disclosure.
- `docs/privacy/dpdp-compliance-checklist.md`: Legal review checklist for DPDP/GDPR alignment.

### 2.8 Comprehensive Testing Suite
- File: `tests/test_p10_security_observability_dr.py`
- Tests covering:
  - `test_REQ_3_1_tls_transport_enforced`: Validates TLS enforcement in configuration and closed failure on TLS issues.
  - `test_REQ_11_4_threat_model_verification`: Automated tests for threat model rows (IDOR, credential revocation, token replay, URL leak, malicious upload, admin compromise, tenant spoofing, log secrets, cache leakage).
  - `test_REQ_12_2_agent_silence_alerts_work_and_sleep_hours`: Validates silence alerts fire only during work hours when awake/unlocked.
  - `test_E88_log_redaction_secrets_filter`: Validates tokens and passwords are redacted from log records.
  - `test_E86_backup_restore_and_consistency_verification`: Validates backup creation, restore flow, and DB-to-storage consistency checker.
  - `test_E87_degraded_mode_and_failover_handling`: Validates readiness checks report degraded state when dependencies are unreachable.
  - `test_health_and_readiness_endpoints`: Validates `/health/live`, `/health/ready`, and `/metrics`.
  - `test_security_headers_and_payload_caps`: Validates CSP, HSTS, X-Frame-Options, and payload caps.
