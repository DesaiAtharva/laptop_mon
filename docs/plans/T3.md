## 1. Objectives & Scope

Prompt T3 validates the complete Laptop Productivity Monitoring SaaS by executing real browser user journeys using **Playwright (Chromium)** against the production frontend build (`frontend/dist`), Django live server, MySQL transactional database, object storage, and desktop agent.

### Core Goals:
1. **Role-Based Workflows**:
   - **Employee**: Transparency banner, self-view metrics, active/idle time, registered devices, dispute submission. Negative authorization tests: opening admin console or other employee data is denied.
   - **Manager**: Team dashboard, team member status, aggregate productivity. Negative authorization tests: viewing other teams or admin settings is denied.
   - **Organization Admin**: Admin console, policy management with optimistic concurrency (E99), fleet inventory, device enrollment, device revocation.
   - **Auditor**: Audit trail view, compliance inspection, verification of append-only audit entries. Negative authorization tests: editing policies is denied.
   - **Platform Support**: Break-glass support session with time-bounded token, explicit tenant context, and full audit logging.
2. **SQL vs UI Cross-Check**:
   - Extract rendered metric values from the browser DOM and compare directly against SQL rows in `DailyMetrics` and `AppUsageInterval`. Verify exact active seconds, idle seconds, productive share, timezone conversions (Local vs UTC), and `calc_version`.
3. **Admin Actions with Real Agent Effect**:
   - Create enrollment token in browser -> Agent core enrolls device -> Device record created.
   - Change policy in browser -> Agent core syncs and receives new version.
   - Revoke device in browser -> Agent core upload rejected with 403; agent halts uploads per policy.
4. **Screenshot Vault & Gallery Flow**:
   - Gallery view with explicit screenshot permission.
   - Presigned view URL generated and validated.
   - Expired view URL returns 403 / expired state.
   - Audit trail logs `screenshot.viewed` for every view.
5. **Optimistic Concurrency Policy Conflict (E99)**:
   - Simultaneous edits against same policy version; second update triggers 409 Conflict screen.
6. **Disconnect & Reconnect Flow**:
   - Agent generates events offline while disconnected; reconnects and drains journal; UI freshness indicators update.
7. **Cross-Tenant Isolation & Accessibility**:
   - Multi-tenant tenant switcher (E46); cross-tenant ID injection rejected.
   - Viewport resizing (desktop 1280x800 and tablet 768x1024), semantic headings, unique button IDs.
   - Capture browser screenshots to `docs/test-evidence/screenshots/t3/`.

## 2. Test Architecture

```
[Playwright Chromium Headless]
             │
             ▼ HTTP (port 3000 / proxy)
[Static & Reverse-Proxy Server]
   ├── Static assets: frontend/dist (HTML, JS, CSS)
   └── API proxy (/api/*) ──► [Django LiveServer (TestCase)]
                                    ├── MySQL transactional models
                                    ├── Object storage backend
                                    ├── Celery tasks (inline/direct)
                                    └── Agent Core SyncWorker / Journal
```

### Components:
- **Test Runner**: Django `LiveServerTestCase` combined with Python `playwright.sync_api`.
- **Frontend Delivery**: Built static bundle (`frontend/dist/index.html`, `frontend/dist/assets/`) served via a local lightweight HTTP proxy server that forwards `/api/*` to the live Django server.
- **Data Generation**: Pre-seeded database and agent simulator generating authentic events, screenshots, intervals, and metrics.
- **Evidence Storage**: Playwright captures screenshots of each primary role and modal state to `docs/test-evidence/screenshots/t3/`.
