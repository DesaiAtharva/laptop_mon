## 1. Objectives

Build a comprehensive, reusable fault-injection harness and automated test suite (`tests/test_t4_fault_injection.py`) verifying that the entire Laptop Productivity Monitoring SaaS system adheres strictly to the **7 Invariants** defined in **Specification §14.3**:

1. **No accepted event lost** — Durable write before server acknowledgement; agent deletes local journal records *only* after confirmed acceptance.
2. **No duplicate contribution to any metric** — Ingestion, timeline reconstruction, and daily metric calculation are strictly idempotent under replayed or duplicate batches.
3. **Every gap flagged as a gap** — Missing telemetry (crashes, shutdowns, power losses, offline quota pruning) is recorded explicitly as an unknown gap — never inferred as active, idle, or productive work.
4. **No fabricated activity** — Telemetry is never invented under any failure condition.
5. **No plaintext uploaded** — Journal events and screenshots are encrypted with AES-256-GCM at rest, transport uses TLS, and sensitive credentials/tokens are redacted by default.
6. **Automatic recovery without manual steps** — All recoverable faults self-heal cleanly upon restoration of connectivity, disk, or services.
7. **Clear reporting for unrecoverable faults** — Permanent or unrecoverable issues (e.g. fatal corruption, hardware revocation) trigger structured, actionable error diagnostics.

## 3. Architecture of the Fault Injection Harness

The test file `tests/test_t4_fault_injection.py` will feature:
1. `FaultInjectionHarness`: Context managers and interceptors to inject failures at exact code execution points (simulated socket drops, disk limits, database deadlocks, file corruptions).
2. `RandomizedJitter`: Parametrized and randomized timing execution to verify resilience under asynchronous concurrency and race conditions.
3. Invariant Assertion Helpers:
   - `assert_no_event_loss(original_events, stored_events)`
   - `assert_metric_idempotency(tenant_id, device_id)`
   - `assert_explicit_gap_emitted(journal)`
   - `assert_zero_plaintext_leak(data_bytes)`
