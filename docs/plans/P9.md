## 1. Objectives & Scope

1. **Billing & Subscriptions (`backend/apps/billing/`):**
   - Models (§7.2, §15.3):
     - `Plan`: name, seat_limit, price_per_seat_cents, features, is_active.
     - `Subscription`: tenant (OneToOne), plan, status (active, trialing, past_due, canceled), seat_count, current_period_start, current_period_end, cancel_at_period_end, external_id.
     - `UsageRecord`: tenant, subscription, active_seats, active_devices, recorded_at.
     - `WebhookEvent`: event_id (unique), provider, event_type, payload, status, created_at (idempotency store).
   - Quota Enforcement (REQ-15-3):
     - Server-side validation on device enrollment (`check_subscription_seat_limit`) enforcing `subscription.seat_count` / plan limits. Rejects device enrollment if seat quota is exceeded (E85).
2. **Webhook Ingestion Engine & State Machine (E84):**
   - Endpoint: `POST /api/billing/webhook/`
   - Cryptographic signature verification using HMAC-SHA256 (`Stripe-Signature` or `X-Webhook-Signature`).
   - Idempotent processing: duplicate events are detected and acknowledged without state corruption (E84).
   - Order-independent state machine: event timestamps compared to ensure newer state is never overwritten by delayed out-of-order webhooks (E84).
   - Audited with `log_audit_event`.
3. **Invitation Pipeline & Email Delivery (E83):**
   - Invitations created by Org Admins (`POST /api/tenants/{id}/invitations/`).
   - Integrated with Django email backend (`send_mail`).
   - Safe error handling on email delivery failure (E83):
     - Catches SMTP / network delivery exceptions.
     - Preserves invitation record and flags `delivery_status="failed"` with error message.
     - Allows resending / manual invitation link retrieval.
   - Endpoint: `POST /api/invitations/accept/` to redeem tokens and activate memberships.
4. **Tenant Lifecycle (E43, E44):**
   - Tenant suspension (`TenantStatus.SUSPENDED`):
     - Blocks UI & API authentication immediately (403 `TENANT_SUSPENDED`).
     - Agent batch uploads & heartbeat reject or fail closed gracefully under policy.
   - Tenant deletion (`TenantStatus.DELETING`):
     - Blocks access immediately.
     - Staged verified deletion across MySQL tables (memberships, devices, credentials, policies, activity events, intervals, metrics, screenshots), Redis cache, and S3 object keys.
     - Audited and immutable record.
   - Runbook: `docs/runbooks/tenant-lifecycle.md`.

## 2. Requirements & Edge Cases Covered

- **REQ-15-3:** Per-tenant quotas MUST be enforced server-side.
- **E43:** Tenant suspended (access blocked, agent pauses).
- **E44:** Tenant deleted (immediate block, staged verified cascade deletion).
- **E83:** Invitation email delivery fails (safe exception handling, delivery status tracked, resend available).
- **E84:** Payment webhook duplicated or out of order (signature check, idempotency table, order-independent state machine).
- **E85:** Subscription limit reached (server-side seat count rejection).
