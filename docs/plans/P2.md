## 2. Assumptions & Invariants

1. **Tenant Derivation:** Tenant ID is derived strictly from the enrolled device / authenticated credential — **never** accepted from the request body or agent headers.
2. **Device Authentication:** Per-device rotating bearer secrets or public-key authentication (`DeviceBearer <secret>`), stored securely hashed (SHA-256) in `agent_credentials`. Universal secrets are forbidden.
3. **Immutability:** Raw activity events accepted by the server are immutable.
4. **Idempotent Batch Processing:** A repeated batch upload with identical events returns the exact same accepted status. Different payloads for the same event ID trigger a 409 Conflict and an audit integrity alert.
5. **Partial Batch Acceptance:** Batches containing a mix of valid, duplicate, and invalid events accept valid ones, record duplicates as `already_accepted`, and return explicit lists in the JSON response.

## 3. Architecture & Module Design

### 3.1 Django Apps
- `backend/apps/devices/`:
  - `Device`: UUID, tenant, membership, hostname, os, status (`active`, `revoked`), agent_version, last_seen_at.
  - `AgentCredential`: UUID, device, secret_hash, status (`active`, `revoked`, `expired`), expires_at, last_used_at.
  - `EnrollmentToken`: UUID, tenant, membership, token_hash, expires_at, used_at, max_uses, use_count, created_by.
  - Endpoints: `POST /api/devices/enrollment-tokens`, `POST /api/agent/enroll`, `POST /api/devices/{id}/revoke`, `POST /api/devices/{id}/reassign`.
- `backend/apps/policies/`:
  - `MonitoringPolicy`: UUID, tenant, version (optimistic locking), valid_until, screenshot_interval_seconds, idle_threshold_seconds, retention_days, capture_windows, exclusion_rules, window_title_collection, min_agent_version, max_agent_version, effective_date.
  - `AppRule`: UUID, tenant, policy, app_identifier, classification, version.
  - Endpoints: `GET /api/agent/policy`, `GET /api/policies`, `PATCH /api/policies/{id}`.
- `backend/apps/ingestion/`:
  - `WorkSession`: UUID, device, tenant, started_at, ended_at, end_reason, session_type.
  - `ActivityEvent`: UUID (client-generated), device, tenant, event_type, occurred_at, received_at, payload, batch, upload_status.
  - `EventBatch`: UUID, device, tenant, received_at, agent_version, schema_version, total_events, accepted_count, status.
  - Endpoints: `POST /api/agent/heartbeat`, `POST /api/agent/events/batch`.

### 3.2 Ingestion Engine Workflow
```
[Agent] ──POST /api/agent/events/batch──► [IngestionView]
                                                 │
                             ┌───────────────────┴───────────────────┐
                     [Authenticate Device]                   [Check Rate Limit]
                             │                                       │
                     [Validate Device Active]                [Validate Batch Size]
                             │
                     [Loop Events in Batch]
                             ├─ Unknown event type ──────────► rejected (code: unknown_event_type)
                             ├─ Implausible timestamp ───────► flagged anomaly (E25)
                             ├─ Duplicate ID + same payload ─► already_accepted (E31)
                             ├─ Duplicate ID + diff payload ─► 409 Conflict + alert (E32)
                             └─ Valid event ─────────────────► accepted & staged
                             │
                     [Atomic Commit to DB]
                             │
                     [Return 200/207 Summary: accepted, already_accepted, rejected]
```

## 4. Test Strategy

1. **Device Enrollment & Credentials:** Single-use tokens, expiration, replay prevention (E39), seat limit hook (E85), re-imaging (E23).
2. **Device Revocation & Reassignment:** Immediate server-side rejection for revoked devices (E24, E38), OS user reassignment (E98).
3. **Policy Engine & Heartbeat:** Version negotiation, upgrade-required responses (E16), offline grace window (E37), optimistic locking with audit on conflict (E99).
4. **Batch Ingestion & Idempotency:** Identical payload duplicate handling (E31), conflicting payload 409 (E32), unknown event type (E33), oversized batch 413 (E34), rate limiting (E35), partial acceptance (E36), clock drift detection (E02, E03, E25).
