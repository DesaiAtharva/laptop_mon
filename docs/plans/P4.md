# Plan P4: Analytics Engine, Metrics & Reports API

## 1. Overview & Objectives

Implement the analytics engine, timeline reconstruction state machine, daily metrics aggregation, Celery job resilience, and reports/exports API for the Laptop Productivity Monitoring SaaS exactly per:
- Spec sections: §9 (Timeline and productivity calculations), §7.2 (`AppUsageIntervals`, `DailyMetrics`), §8.4 (Dashboard & Reports API), §10.3 (Storage capacity formula), §11.1 (Audit logging), §11.4 (Negative authorization & role scoping).
- Non-negotiable product rules in `AGENTS.md`:
  - Never invent data: missing telemetry is an explicit unknown gap (`telemetry-gap`), never active, idle, or productive time.
  - Raw accepted events are immutable. Derived data is recomputable and carries `calc_version`.
  - Deterministic state machine: sorted by `(occurred_at, source_sequence, event_id)`.
  - No overlapping intervals per device.
  - Impossible sequences normalized, recorded as anomalies, never negative durations.
  - Authorization on every request and every Celery task.
  - Bounded retries on deadlock, idempotency on task retry.

## 2. Traceability & Edge Cases Covered

- **Requirements:**
  - `REQ-1-2`: Foreground application usage
  - `REQ-1-3`: Session activity (active/idle/locked)
  - `REQ-8-3`: Authorization on every request and every Celery task
  - `REQ-9-1`: Timeline reconstruction MUST be deterministic
  - `REQ-9-2`: No overlapping intervals per device
  - `REQ-9-3`: Gaps MUST be explicit unknowns — never filled or counted as activity
  - `REQ-9-4`: Impossible sequences MUST be normalized, recorded as anomalies, never produce negative durations
  - `REQ-9-5`: Daily metrics MUST have a unique grain; recalculation MUST be idempotent
- **Edge Cases:**
  - `E25`: Device clock far off (timeline separate handling)
  - `E26`: Clock changes while running (monotonic check / jump handling)
  - `E27`: Timezone changes (preserves UTC instants, converts to local date using tenant IANA timezone)
  - `E28`: DST 23 or 25 hour day (IANA timezone math without shifting instants)
  - `E29`: Duplicate timestamps (deterministic secondary sort: `source_sequence`, `event_id`)
  - `E30`: Events arrive out of order (sorted before state machine evaluation)
  - `E58`: Sleep, hibernate and wake reconciled (creates asleep intervals, handles missing wake)
  - `E66`: App identifier unavailable (marked `unclassified`)
  - `E69`: App classification changes (triggers versioned recalculation with updated `calc_version`)
  - `E70`: Idle threshold changes (versioned recalculation)
  - `E71`: Session never receives end event (closed provisionally and labeled `inferred`)
  - `E72`: Idle end without idle start (normalized, recorded as anomaly, non-negative duration)
  - `E73`: Overlapping app intervals prevented (guaranteed non-overlapping interval sequence)
  - `E74`: Late event changes daily totals (targeted recalculation of affected window + safety overlap)
  - `E75`: Worker retries same job (idempotent Celery execution with task lock)
  - `E76`: Celery or Redis unavailable (raw events remain durable in DB, caught up later)
  - `E77`: MySQL failover or deadlock (bounded retry decorator with exponential backoff)
  - `E79`: Connection pool sizing and query timeouts
  - `E81`: Report query too large (paginated, query budgets, max date ranges)
  - `E82`: Export exceeds limits (row caps, background worker, authorization rechecked)

## 3. Architecture & Key Components

1. **Modular App `apps.analytics`:**
   - **`models.py`**:
     - `AppUsageInterval`: `device`, `tenant`, `app_identifier`, `app_classification`, `app_classification_version`, `started_at`, `ended_at`, `duration_seconds`, `state`, `calc_version`, `is_inferred`.
     - `DailyMetrics`: `device`, `tenant`, `local_date`, `calc_version`, `observed_session_seconds`, `active_seconds`, `idle_seconds`, `productive_seconds`, `neutral_seconds`, `distracting_seconds`, `productive_share`, `monitoring_coverage`, `sync_lag_seconds`, `crash_free_sessions`, `data_freshness_at`. Unique constraint on `(device, local_date, calc_version)`.
     - `DataExport`: `tenant`, `user`, `status`, `export_type`, `filters`, `file_key`, `row_count`, `expires_at`.
   - **`timeline.py`**:
     - Deterministic state machine reconstructor: sorts events by `(occurred_at, source_sequence, event_id)`, walks transitions, maintains current foreground app, session, lock, sleep, idle, and gap states.
     - Produces clean list of non-overlapping `AppUsageInterval` records.
   - **`metrics.py`**:
     - Takes reconstructed intervals, groups by tenant IANA local date, computes daily aggregates, writes `DailyMetrics`.
   - **`tasks.py`**:
     - Celery tasks with runtime authorization check (`REQ-8-3`), idempotency lock (`E75`), and deadlock retry (`E77`).
     - `process_device_timeline_task`, `export_dataset_task`.
   - **`capacity.py`**:
     - Formula helper for §10.3 storage planning.
   - **`views.py` & `urls.py`**:
     - `GET /api/reports/daily`
     - `GET /api/reports/timeline`
     - `GET /api/reports/app-usage`
     - `POST /api/exports`
     - `GET /api/exports/{id}`
     - Role scoping (Manager assigned teams, Employee own device, Admin all).
     - Query budgets and date range constraints.

4. **Testing Strategy (`tests/test_p4_analytics_timeline_reports.py`):**
   - Property tests on out-of-order and duplicate timestamps (E29, E30).
   - Verification that no overlapping intervals exist per device (REQ-9-2, E73).
   - Telemetry gap handling (REQ-9-3).
   - Anomaly normalization and negative duration prevention (REQ-9-4, E72).
   - Inferred unclosed session handling (E71).
   - DST 23/25 hour day and timezone handling (E27, E28).
   - App classification change and late event recalculation (E69, E74).
   - Celery task retry idempotency and deadlock recovery (E75, E77).
   - Query limits and export row limits (E81, E82).
