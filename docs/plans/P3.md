# Plan P3: Screenshot Backend, Storage, Upload Authorization, Verification, Retention & Legal Hold

## 1. Overview & Objectives

Implement the screenshot pipeline and storage backend for the Laptop Productivity Monitoring SaaS exactly per:
- Spec sections: §6.2 (Screenshot upload protocol), §7.2 (`Screenshots` model), §8.3 & §8.4 (Screenshot endpoints), §10 (Screenshot pipeline and storage), §11.1 & §11.2 (Audit logging, legal hold, data handling).
- Non-negotiable product rules in `AGENTS.md`:
  - No image bytes in MySQL — object keys only.
  - Tenant-scoped and non-guessable object keys.
  - Transparent, policy-driven, auditable monitoring.
  - Strict untrusted upload verification (type, dimensions, decompression bomb bounds).
  - Short-lived, single-object presigned URLs; URLs never logged.
  - Two-phase upload protocol with idempotent finalize and retry.
  - Deletion verification on retention sweeps; backlog metric reporting.
  - Legal hold workflow preventing deletion of eligible data.

## 2. Traceability & Edge Cases Covered

- **Requirements:**
  - `REQ-1-4`: Periodic screenshots backend
  - `REQ-6-3`: Two-phase upload protocol (intent + complete), idempotent
  - `REQ-10-1`: Screenshots MUST NOT be stored in MySQL — only object keys
  - `REQ-10-2`: Object keys MUST be tenant-scoped and non-guessable
  - `REQ-10-3`: Every upload MUST be treated as untrusted (strict decode, type/dimension limits)
  - `REQ-10-4`: View URLs MUST be short-lived, scoped to one object, and every view audited; URLs never logged
  - `REQ-11-2`: Legal hold MUST prevent deletion of eligible data
- **Edge Cases:**
  - `E49`: Screenshot view URL leaked -> short-lived (300s), scoped to 1 object, audited, URL never logged in DB or logs, expired URL unusable.
  - `E50`: Malicious uploaded file -> strict decode with Pillow, dimension/type check, decompression bomb limit, malware scan hook, never execute.
  - `E51`: Screenshot upload partially completes -> intent reuse, never duplicate records, orphan reconciliation.
  - `E52`: Upload succeeded, finalize failed -> finalize retry idempotently verifies object and completes.
  - `E53`: Finalize succeeded, response lost -> idempotent retry returns 200 OK with finalized metadata.
  - `E54`: Retention job fails -> verify deletion, alert on failure, expose backlog metric, never report completion before verification.
  - `E55`: Screenshot exclusion rule added -> retroactive policy handling (`keep`, `purge`, `flag_legal_review`).
  - `E90`: Legal retention or deletion request -> authority check (Admin only), hold flag prevents deletion during sweep, legal deletion deletes eligible data, audited without sensitive content.

## 3. Architecture & Key Components

1. **Storage Subsystem (`backend/apps/screenshots/storage.py`):**
   - Abstraction `ObjectStorageBackend` with MinIO / S3 implementation and in-memory/filesystem testing storage.
   - Tenant-scoped non-guessable key format:
     `tenants/{tenant_id}/devices/{device_id}/{year}/{month}/{day}/{uuid}.{ext}`
   - Presigned upload URL generation (PUT or POST with expiration).
   - Presigned view URL generation (GET with short expiration, e.g. 300s).
   - Verification of existence, size, and checksum.
   - Deletion and deletion verification.

2. **Data Model (`backend/apps/screenshots/models.py`):**
   - `ScreenshotStatus`: `pending`, `uploaded`, `finalized`, `failed`, `deleted`.
   - `Screenshot`:
     - UUID primary key, `device` (FK), `tenant` (FK), `status`, `object_key`, `thumbnail_key`, `captured_at`, `width`, `height`, `file_size`, `checksum`, `policy_version`, `delete_after`, `legal_hold` (bool), `retroactive_action` (optional).
     - State transition validation.
   - `ScreenshotUploadIntent`:
     - Intent tracking for upload URLs, expiration, and reuse.
   - `LegalHoldRecord`:
     - Tracking legal holds applied to tenants, devices, or screenshot sets.

3. **Core Services (`backend/apps/screenshots/services.py`):**
   - `create_upload_intent(...)`: handles intent generation, device active check, policy check, intent reuse for partially completed or expired intents (E51–E53).
   - `complete_screenshot_upload(...)`: verifies S3 object exists, validates checksum, strictly decodes image via Pillow (E50), checks dimensions, generates thumbnail, idempotently transitions to `finalized` (E52, E53).
   - `generate_screenshot_view_url(...)`: checks screenshot permissions, tenant isolation, generates short-lived presigned URL, writes audit log, prevents logging of URL (E49).
   - `run_retention_sweep(...)`: finds expired non-held screenshots (`delete_after <= now() and not legal_hold`), deletes from S3, verifies deletion, marks `deleted`, logs failures, tracks backlog metric (E54).
   - `apply_legal_hold(...)` & `release_legal_hold(...)`: sets/clears legal hold flag (E90).
   - `execute_legal_deletion(...)`: admin-authorized deletion of held or requested data, audited without sensitive content (E90).
   - `apply_retroactive_exclusion(...)`: applies retroactive handling for newly excluded apps/rules (E55).
   - `reconcile_orphan_objects(...)`: finds incomplete or unfinalized uploads past grace period (E51).

4. **API Endpoints (`backend/apps/screenshots/views.py`):**
   - `POST /api/agent/screenshots/upload-intents` (Agent auth)
   - `POST /api/agent/screenshots/complete` (Agent auth)
   - `GET /api/screenshots` (User auth + screenshot permission)
   - `POST /api/screenshots/{id}/view-url` (User auth + screenshot permission)
   - `POST /api/screenshots/legal-hold` (Admin auth)
   - `POST /api/screenshots/legal-delete` (Admin auth)

5. **Test Suite (`tests/test_p3_screenshots_storage_retention.py`):**
   - Negative authorization tests across all endpoints.
   - IDOR / cross-tenant tests.
   - Tests for all edge cases E49, E50, E51, E52, E53, E54, E55, E90.
   - Traceability updates and verification script execution.
