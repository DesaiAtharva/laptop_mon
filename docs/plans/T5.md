# Implementation Plan — Prompt T5: Security and Tenant Isolation

> **Prompt:** T5 (Security and tenant isolation)  
> **Rulebook:** `AGENTS.md`  
> **Specification:** §§ 2, 7, 8, 10, 11, 11.4  
> **Date:** 2026-10-28  
> **Author:** Antigravity Agent  

---

## 1. Goal & Requirements

Build a comprehensive security and isolation automated test suite (`tests/test_t5_security_tenant_isolation.py`) and deliver verifiable evidence in `docs/test-evidence/T5.md`.

The suite must guarantee that:
1. **Cross-Tenant Isolation (`AC-5`, `RC-07`, `E45`):** No authenticated user or device belonging to Tenant A can view, modify, list, or infer the existence of resources belonging to Tenant B across any endpoint.
2. **Role-Based Access Control (`REQ-2-1` to `REQ-2-7`, `§11.1`):** Every role (Employee, Manager, Admin, Auditor) is strictly bounded by least privilege; negative authorization tests pass for every privileged action.
3. **Session & Auth Security (`E48`):** Privilege escalation blocked; sessions revoked upon credential/password changes; MFA required for privileged operations.
4. **Agent Credential Boundary (`REQ-3-2`, `E39`, `E40`):** Single-use enrollment tokens, per-device scoped secrets, rejection of token replay and device impersonation. Tenant spoofing in agent payloads is ignored; tenant is derived solely from server-side device authentication.
5. **Screenshot Storage Hardening (`REQ-10-2`, `REQ-10-3`, `E49`, `E50`):** Scoped short-lived presigned URLs, decompression bombs and malware test signatures rejected, tamper-evident checksum validation.
6. **Fuzzing & Payload Abuse (`E33`, `E35`):** Malformed JSON, SQL injection strings, header injection, and oversized payloads handled cleanly; rate limits return HTTP 429 with `Retry-After`.
7. **Secret Scrubbing & Log Redaction (`RC-10`, `E88`):** Repository, logs, crash dumps, and installers scanned to prove zero credential, token, or private key leaks. Tenant-scoped cache keys verified (`E80`).
8. **Threat Table Verification (`REQ-11-4`, `§11.4`):** Every row in the Section 11.4 threat model has a dedicated automated test.

## 2. Architecture & Test Suite Design

The test suite will be implemented in `tests/test_t5_security_tenant_isolation.py` using Django's real test database and real object storage.

### Domain Coverage Matrix
We will seed two distinct tenants (`Tenant Alpha` and `Tenant Beta`) with full role matrices:
- `Tenant Alpha`:
  - `Admin Alpha` (Org Admin, MFA enabled)
  - `Manager Alpha` (Manager of Team Engineering)
  - `Employee Alpha 1` (Member of Team Engineering)
  - `Employee Alpha 2` (Member of Team Design)
  - `Auditor Alpha` (Auditor role)
  - `Device Alpha 1` (Active laptop)
- `Tenant Beta`:
  - `Admin Beta` (Org Admin)
  - `Employee Beta` (Member)
  - `Device Beta 1` (Active laptop)

### Test Modules within `test_t5_security_tenant_isolation.py`:
1. `TestCrossTenantObjectIsolation`:
   - Endpoint by endpoint testing:
     - `/api/tenants/{id}/`
     - `/api/memberships/{id}/`
     - `/api/devices/{id}/`
     - `/api/policies/` & `/api/policies/{id}/`
     - `/api/screenshots/{id}/view/` & `/api/screenshots/gallery/`
     - `/api/analytics/employee/self/` & `/api/analytics/manager/team/`
     - `/api/disputes/{id}/`
     - `/api/audit-logs/`
     - `/api/support-access/requests/`
     - `/api/billing/subscription/`
   - Assert all cross-tenant requests return 403 or 404 without data disclosure.

2. `TestRoleBasedAccessControl`:
   - Negative authorization tests:
     - Employee accessing policy edit (403).
     - Employee accessing audit logs (403).
     - Manager accessing billing or tenant settings (403).
     - Manager accessing teams outside their management scope (403/404).
     - Auditor attempting POST/PATCH/DELETE on policy, device, or membership (403/405).
     - Unauthenticated requests blocked on all non-public routes (401).

3. `TestAuthSessionPrivilegeEscalation`:
   - Member attempting to update membership role to `admin` or grant `has_screenshot_permission` (403).
   - Session revocation: password change revokes active session tokens (`UserSession`).
   - MFA enforcement: privileged actions fail closed if MFA is required but unverified.
   - Invitation enumeration: public invitation validation does not leak tenant membership or email presence.

4. `TestAgentCredentialAndPayloadSecurity`:
   - Enrollment token single-use check: reused token returns 400/409 (`E39`).
   - Expired enrollment token rejected.
   - Device A using valid bearer token targeting Device B's ID in batch ingestion returns 403 (`E40`).
   - Tenant spoofing: agent passes `tenant_id: <Beta>` in JSON body; server derives tenant exclusively from credential (`Alpha`).
   - Batch replay & tamper: duplicate event with identical payload dedupes idempotently; duplicate event with modified payload triggers 409 Conflict & security audit log (`E31`, `E32`).

5. `TestScreenshotPipelineHardening`:
   - Presigned view URL generated by Tenant Alpha cannot be accessed or requested by Tenant Beta (`E49`).
   - Expired presigned URL rejected.
   - Decompression bomb image (`> 35,000,000` pixels) rejected with validation error (`E50`).
   - Malware test signatures (EICAR, DOS MZ, ELF magic) rejected upon upload (`E50`).
   - Oversized screenshot (`> 10MB`) rejected (`E50`).

6. `TestPayloadAbuseFuzzingAndRateLimiting`:
   - Malformed JSON payloads handled cleanly (400 Bad Request, no unhandled 500 crashes).
   - SQL injection / XSS strings in search, filters, and window titles safely escaped.
   - Rate limit enforcement: rapid requests exceed per-device threshold and return 429 with `Retry-After` header (`E35`).

7. `TestSecretsScrubbingAndCacheIsolation`:
   - Codebase, installer scripts, and log outputs scanned for leaked secrets, API keys, or private key material (`E88`, `RC-10`).
   - Cache key isolation: verify that tenant cache operations always include tenant prefix (`tenant:{id}:...`) preventing cross-tenant cache contamination (`E80`).

8. `TestThreatModelMatrixCoverage`:
   - Systematic assertions verifying all 10 threat table rows from Specification §11.4.

## 3. Step-by-Step Implementation Steps

1. Create `tests/test_t5_security_tenant_isolation.py` implementing all test cases described above.
2. Run test execution:
   `python backend/manage.py test tests.test_t5_security_tenant_isolation --settings=config.settings.testing`
3. Fix any authorization edge cases or discrepancies discovered.
4. Run full test suite regression:
   `python backend/manage.py test tests --settings=config.settings.testing`
5. Run migration check:
   `python scripts/check_migrations.py`
6. Run traceability check:
   `python scripts/check_traceability.py`
7. Produce evidence report in `docs/test-evidence/T5.md`.
8. Update `TRACEABILITY.md` for `AC-5`, `RC-06`, `RC-07`, `RC-10`, and T5 requirements.
9. Commit and generate final report per `AGENTS.md`.
