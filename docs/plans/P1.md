## 2. Assumptions

1. **Storage & Database:** Running in dev/test using SQLite in-memory or MySQL (configured via `DATABASE_URL` or standard Django `DATABASES` settings). Models adhere strictly to InnoDB utf8mb4 conventions, foreign keys, and UUID primary keys.
2. **Tenant Extraction:** Multi-tenant users supply the active tenant context via `X-Tenant-ID` header. If a user belongs to exactly one active tenant, it defaults to that tenant. If ambiguous or missing, the request receives a `400 Bad Request` or prompts tenant selection via `/api/me/tenants`. Tenant is **never** accepted from the request body.
3. **OIDC Simulation / Integration:** Real OIDC endpoint supports state and nonce verification; test harness can mock cryptographic signature verification while enforcing strict flow state and nonce checks.
4. **Append-Only Audit Logs:** Enforced at the model level (`delete()` and `update()` disallowed, queryset update overridden/prevented) and application service layer.
5. **No destructive migrations without approval (E78):** A migration checker script validates that migrations do not drop columns or tables without explicit annotation.

## 3. Architecture & Module Design

### 3.1 Django Project Structure
```
backend/
├── manage.py
├── config/
│   ├── __init__.py
│   ├── asgi.py
│   ├── wsgi.py
│   ├── urls.py
│   └── settings/
│       ├── __init__.py
│       ├── base.py
│       ├── development.py
│       ├── production.py
│       └── testing.py
└── apps/
    ├── common/          # RequestID middleware, standard error handler (§8.1), tenant-scoped cache key helper (E80), base models
    ├── accounts/        # Custom User model (UUID, MFA), OIDC callback, session revocation (E48), token/session auth
    ├── tenancy/         # Tenant, Membership, Team, TeamMember models with composite constraints, tenant managers/querysets
    ├── rbac/            # Permission classes, role definitions, team scoping, screenshot permission flag
    ├── audit/           # Append-only AuditLog model, audit service, audit middleware, audit log endpoint
    └── support_access/  # Just-in-time support request, approval workflow, time-bound access, E100 enforcement
```

### 3.2 Error Contract (§8.1)
All error responses adhere to:
```json
{
  "code": "machine_readable_code",
  "message": "Human readable message",
  "field_errors": {},
  "correlation_id": "uuid"
}
```

### 3.3 RBAC & Permission Matrix (§2.2)
- **Roles:** `EMPLOYEE`, `MANAGER`, `ORG_ADMIN`, `AUDITOR`, `PLATFORM_SUPPORT`, `SERVICE_IDENTITY`.
- `has_screenshot_permission` is an explicit, separate flag/permission.
- Managers are restricted strictly to assigned teams via `team_members`.
- Cross-tenant requests return a safe `404 Not Found` (or `403 Forbidden` if unauthenticated/unauthorized) without leaking existence of resources in other tenants (E45).
- Tenant status (`ACTIVE`, `SUSPENDED`, `DELETING`) enforced at middleware/permission level (E43, E44).

### 3.4 Edge Case Handlers
- **E41 (Employee moved to another team):** Team membership change immediately updates access; past team data access revoked; audited.
- **E42 (Employee leaves company):** Membership status set to `DISABLED`; active sessions revoked; device revocation hook triggered; audited.
- **E43 / E44 (Tenant suspended / deleted):** Middleware/permission blocks access with safe status code; audited.
- **E45 (Cross-tenant IDOR):** Tenant-scoped querysets ensure foreign IDs raise `Http404` or `PermissionDenied`.
- **E46 (User in multiple tenants):** Multi-tenant membership supported; active tenant resolved from `X-Tenant-ID` header; cross-tenant cache partitioned.
- **E47 (Manager changes teams):** Scope dynamically evaluated against active `team_members` assignments; audited.
- **E48 (Admin account compromised):** MFA enforcement for privileged roles; session revocation endpoint invalidates user sessions immediately.
- **E78 (Migration discipline):** Destructive operations gate in `scripts/check_migrations.py`.
- **E80 (Stale or cross-tenant cache):** `tenant_cache_key(tenant_id, key)` ensures tenant isolation in caching; cache cleared on membership/team change.
- **E100 (Support staff access):** JIT support request, org admin approval, expiry time, full audit trail, no standing screenshot/content access.

## 4. Verification & Test Plan

1. **Unit & Isolation Tests:**
   - Multi-tenant data isolation: Tenant A user cannot view/modify Tenant B resources (E45).
   - Cross-tenant cache isolation: cache keys are strictly isolated (E80).
   - Role matrix test parametrized over all 6 roles against all endpoints.
   - Manager team-scoped visibility test (E41, E47).
   - Membership disable / leave company test (E42).
   - Tenant suspension / deletion enforcement (E43, E44).
   - MFA enforcement and session revocation (E48).
   - Support access workflow and time expiry (E100).
   - Append-only audit log verification (prevents edit/delete).
   - Standard error response format contract validation (§8.1).
2. **CI Migration Gate (E78):**
   - Run `python scripts/check_migrations.py`.
3. **Traceability Gate:**
   - Update `TRACEABILITY.md` for P1 rows.
   - Run `python scripts/check_traceability.py`.
