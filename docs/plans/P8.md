## 1. Objectives & Scope

1. **Backend Endpoints for Employee Self-View & Disputes (§11.3, §8.4, E89):**
   - `GET /api/me/self-view/` — returns employee's current monitoring state, active devices, effective policy rules, data retention policy, privacy notice, and recent activity metrics.
   - `Dispute` model and API (`POST /api/disputes/`, `GET /api/disputes/`, `PATCH /api/disputes/{id}/`):
     - Employees can submit disputes on specific app usage intervals or classifications (E89).
     - Managers can review disputes for their team members (REQ-2-3).
     - Admins can resolve disputes and update app classifications.
   - Audited actions with `log_audit_event`.
2. **Frontend Architecture (`frontend/`):**
   - Vite + React + TypeScript in strict mode.
   - Modern, premium Vanilla CSS design system:
     - Elegant dark mode with HSL tokenized palette, subtle glassmorphism, glowing accents, and micro-interactions.
     - Clean typography using Google Fonts (Inter / Outfit).
     - Responsive grid, role-adaptive layouts, collapsible navigation.
3. **Role-Scoped Dashboard Views:**
   - **Employee Self-View (REQ-2-1, REQ-11-3):**
     - Monitoring status (Active, Paused, Offline, sync lag).
     - Transparency & Privacy card: what is collected, screenshot interval, retention duration, privacy policy review.
     - Personal productivity breakdown (Productive vs Neutral vs Distracting vs Idle vs Gaps).
     - Explicit gap visualization (never hidden or counted as activity).
     - Dispute submission modal for false positives (E89).
   - **Manager Team View (REQ-2-3, E47):**
     - Strictly scoped to assigned teams (`get_manager_accessible_team_ids`).
     - Aggregated team productivity metrics, member activity ranking, and timeline scrubber (E70).
     - Team dispute queue.
   - **Org Admin View:**
     - Members & Team assignments (E41).
     - Device fleet management (enrollment tokens, revoke device).
     - Policy editor with optimistic concurrency locking (`version`) per E99.
     - Screenshot gallery with pagination/virtualization (E69) and on-demand short-lived URL generation with audit logging.
     - Audit logs explorer.
   - **Tenant Switcher (E46):**
     - Global tenant selector header component for multi-tenant users.
   - **Timezone Awareness (E74):**
     - Switchable or detected local browser timezone vs UTC with clear indicator.
4. **Automated Testing:**
   - Backend unit and integration tests in `tests/test_p8_dashboard_and_disputes.py`.
   - Frontend component/view tests or build verification.

---

## 2. Key Assumptions & Constraints

- Modular monolith Django backend; MySQL InnoDB utf8mb4.
- Frontend uses Vite + React 18/19 + TypeScript (`strict: true`).
- Aesthetics must be stunning, state-of-the-art, and responsive.
- Every API request derives tenant from authenticated membership / `HTTP_X_TENANT_ID`.
- No mock implementations outside tests.
