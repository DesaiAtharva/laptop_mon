## 1. Objectives

1. **Agent Footprint & Resource Consumption:**
   - Measure Idle CPU, Active CPU during capture and batch upload, Resident Memory (RSS), Disk Writes per hour, Network Bytes per day, Startup Time, Installed Size, and behavior under a simulated 7-day backlog.
   - Enforce non-negotiable budgets from `AGENTS.md` and fail if any metric regresses by > 20% against `docs/perf/BASELINE.md`:
     - Idle CPU: < 1% average
     - Resident memory: < 80 MB
     - Installed size: < 60 MB
     - Cold startup time: < 5 s
     - Disk writes: < 10 MB/hr

2. **Edge-Case Performance & Capacity Handling:**
   - **`E79` (Connection pool exhausted):** When database connections reach max capacity, backend endpoints return structured 503 / graceful queuing without uncaught crashes.
   - **`E81` (Report query too large):** Requests spanning excessively large date ranges or huge dataset volumes are capped, paginated, or rejected cleanly before exhausting memory.
   - **`E82` (Export exceeds limits):** Data export requests exceeding max export row limits or file size thresholds are bounded with structured errors.
   - **`E94` (Compression differs by OS):** Cross-platform screenshot compression (JPEG and WebP) validates bounded file sizes across simulated OS environments.
   - **`E96` (Battery saver & CPU pressure):** Agent scheduler adapts capture frequencies and throttles upload queues when battery saver mode or CPU pressure is reported.

3. **Backend Ingestion & Query Throughput:**
   - High-throughput mass reconnection burst simulation (concurrent device sync).
   - Ingestion rate measurement (events/sec committed durably).
   - Dashboard report query latency profiling (P50, P95).
   - Retention deletion speed (purge batching).

4. **Capacity Planning & Storage Sizing:**
   - Compute storage per device per day using §10.3 formula:
     $$\text{bytes\_per\_device\_per\_day} = \left(\frac{\text{work\_hours} \times 3600}{\text{screenshot\_interval\_seconds}}\right) \times \text{avg\_compressed\_screenshot\_bytes}$$
   - Write comprehensive capacity planning models to `docs/perf/CAPACITY.md`.

5. **Evidence & Documentation:**
   - Write `docs/test-evidence/T6.md` documenting all measured numbers, before/after metrics, load profiles, and capacity formulas.
   - Update `docs/perf/BASELINE.md` with verified environment measurements.
   - Update `TRACEABILITY.md` to link T6 requirements.

## 2. Test Architecture & Benchmark Design (`tests/test_t6_perf_load_footprint.py`)

### Module 1: Agent Footprint Benchmarks
- Benchmark agent scheduler, journal encryption, and spooling memory footprint using `psutil` or `resource` / `gc`.
- Measure cold start time from module import to operational status.
- Measure disk write volume per 1,000 events committed to SQLite journal.
- Measure compression ratios and screenshot byte sizes across JPEG and WebP.
- Simulate 7-day backlog (e.g. 10,000 queued events and 200 screenshots) to verify steady memory consumption and priority-based throttling.

### Module 2: Edge Cases E79, E81, E82, E94, E96
- `test_E79_database_connection_pool_exhaustion`
- `test_E81_report_query_exceeds_maximum_window`
- `test_E82_export_record_limit_enforcement`
- `test_E94_cross_os_image_compression_bounds`
- `test_E96_battery_saver_and_cpu_pressure_throttling`

### Module 3: Backend Load & Ingestion Throughput
- Ingestion burst: Simulate concurrent device batches hitting `/api/agent/events/batch`.
- Calculate ingestion throughput (batches/sec and events/sec).
- Report query latency: Benchmark `/api/reports/daily` and `/api/reports/timeline`.
- Retention deletion: Purge performance of expired screenshots.
